# 개인 트레이딩 데스크

내 컴퓨터에서만 실행되고 내 컴퓨터에서만 접속할 수 있는(`127.0.0.1`; 휴대폰은 비공개 Tailscale 연결로 접속 가능, 8절) 대시보드입니다. 지표가 표시된 차트, 시장 정보 띠, 손익, 호가와 뉴스, **리서치** 화면(랭킹, 섹터, 관심 폴더, 기업 재무), 그리고 차트에 선을 긋고 시나리오를 제안하는 AI 채팅을 보여 줍니다.
**주문:** Toss 주문은 초안 → 내 승인 → 전송 순서로 진행되고(7절), 활성화해야만 실행되는 자동 규칙도 쓸 수 있습니다(7.8절). **기본값은 DRY RUN**이라, 직접 끄기 전까지는 실제로 아무것도 전송되지 않습니다. 전체 설계는 [docs/ROADMAP.md](docs/ROADMAP.md)(영어)에 있습니다.

> **고지:** 개인 프로젝트를 [MIT 라이선스](LICENSE)로 있는 그대로 공유하며, 어떤 보증도 하지 않습니다.
> 투자 조언이 아니고 AI 채팅은 틀릴 수 있습니다. 승인한 주문과 활성화한 규칙의 책임은 전적으로 본인에게 있습니다.
> 믿을 수 있을 때까지 **DRY RUN**으로 쓰세요.

**친구에게 받았나요?** 모든 것을 본인 것으로 준비해야 합니다. 이 사본에는 원래 주인의 것이 하나도 없습니다:
1. Windows PC(1절), 그리고 내 PC의 IP를 등록한 본인의 **토스증권 Open API** 사용 권한(2.1).
2. 채팅용 본인의 **Anthropic API 키**(2.3): 사용료는 본인이 내고, 예산은 설정에서 정합니다.
   Finnhub(뉴스), FRED, SEC 줄은 선택입니다(2.2, 2.2b, 2.2c).
3. 키는 직접 `.env`에 넣습니다(2.4). `.env`는 공유하지 말고, 채팅에 붙여 넣지 말고, 커밋하지 마세요.
4. **DRY RUN을 켠 채로**(기본값) 먼저 모의 주문으로 모두 시험해 보세요(7.1절).
5. **⚙ 설정 → AI 채팅 → 위험 성향**의 기본값은 **표준**입니다. "공격적"은 계좌 전액을 잃어도 된다고 AI에게
   알리는 설정이니, 정말 그럴 때만 고르세요.

더블클릭해서 실행하는 스크립트는 모두 **`scripts`** 폴더에 있습니다.

## 1. 설치 (처음 한 번)

### 1.1 Python 3.15
1. https://www.python.org/downloads/ 에서 Windows용 Python 3.15를 받아 설치 프로그램을 실행합니다.
2. 설치 첫 화면에서 **"Add python.exe to PATH"**에 체크한 다음 **Install Now**를 누릅니다.
3. 확인: **명령 프롬프트**를 열고(Windows 키 → `cmd` 입력 → Enter) 다음을 실행합니다.
   ```
   py --list
   ```
   `3.15`가 들어간 줄이 보이면 됩니다.

### 1.2 Node.js
1. https://nodejs.org/ 에서 **LTS** 버전을 받아 기본 옵션으로 설치합니다.
2. **새** 명령 프롬프트 창에서 확인합니다.
   ```
   node -v
   ```
   `v26.x.x` 같은 버전 번호가 보이면 됩니다.

### 1.3 프로젝트 패키지
프로젝트 폴더의 **`scripts\setup.cmd`**를 더블클릭합니다. 이 스크립트는:
- `backend\.venv`에 Python 환경을 만들고 Python 패키지를 설치합니다
- `frontend\node_modules`에 화면용 패키지를 설치합니다

마지막에 "Setup finished OK"가 나오면 성공입니다. FAILED가 나오면 바로 위의 메시지를 읽어 보세요. 대개 Python이나 Node가 없는 경우이니 1.1 또는 1.2를 다시 하면 됩니다.

## 2. API 키

키는 **오직** 프로젝트 폴더의 `.env` 파일에만 둡니다. 브라우저로 보내지지 않고, 화면에 표시되지 않으며, git에 커밋되지도 않습니다.
화면에는 각 키가 "set"(설정됨)인지 "empty"(비어 있음)인지만 표시됩니다.

### 2.1 토스증권 Open API (필수: 시세, 캔들, 환율)
1. 토스증권 Open API 개발자 사이트에 로그인합니다: https://developers.tossinvest.com/
2. 앱을 만들고 **Client ID**와 **Client Secret**을 복사합니다.
3. 토스증권 WTS에서 **이 컴퓨터의 IP 주소를 등록**합니다: **설정 > Open API > 허용 IP**.
   공인 IP는 브라우저에서 https://www.whatismyip.com/ 을 열면 나오는 "IPv4" 값입니다.
   이 단계를 건너뛰면 Toss가 모든 요청을 거부하고, 화면에 "Toss WTS(설정 > Open API)에 이 PC의 IP를 등록하세요"가 표시됩니다.
   공유기 재시작 등으로 집 IP가 바뀌면 새 IP를 다시 등록하세요.

대시보드는 **한 번에 하나만** 실행할 수 있습니다. 실행할 때마다 Toss 토큰을 새로 받는데, 새 토큰이 나오면 이전 토큰은 무효가 되기 때문입니다.
화면에 "다른 곳에서 토큰이 교체됨"이 나오면 다른 창을 닫고, 노란 띠의 **Toss 다시 시도**를 누르세요.

### 2.2 FRED (선택: 미국 10년물 국채 금리 공식값)
1. https://fredaccount.stlouisfed.org/ 에서 무료 계정을 만들고 **API Keys** 메뉴에서 키를 신청합니다.
2. 이 키가 없으면 "10Y FRED" 칸에 "키 없음"이 표시되고, 나머지는 모두 정상 작동합니다.

### 2.2b Finnhub (뉴스 피드)
1. https://finnhub.io/ 에서 무료 계정을 만들고 대시보드에서 API 키를 복사합니다.
2. `.env`에 `FINNHUB_API_KEY=...`로 넣습니다(`env.example`에는 이름만 `FINNHUB_API_KEY=`).
3. 키가 없으면 뉴스 패널에 ".env에 FINNHUB_API_KEY를 넣고…"가 표시되고, 나머지는 정상 작동합니다.
리서치 화면도 이 키로 기업 개요, 최근 4분기 EPS 서프라이즈, 실적 발표 일정, 애널리스트 의견을 가져옵니다.
Finnhub는 북미 기업(미국 주식·ETF)을 다룹니다. Massive(`MASSIVE_API_KEY`)는 선택 백업이며, 문서에서 API 주소를 확인하지 못해 지금은 **꺼져** 있습니다.

### 2.2c SEC EDGAR (리서치: 기업 재무제표, 키 불필요)
SEC는 재무제표를 무료로 주지만, 모든 앱에 누가 요청하는지 밝히도록 요구합니다.
1. `.env`에 `SEC_USER_AGENT=`를 이름과 이메일로 넣습니다. 예: `SEC_USER_AGENT=Trading Desk your.name@example.com` (영문·숫자·일반 기호만).
2. 이 값은 SEC에만 보내고, 로그나 화면에는 절대 나오지 않습니다.
3. 없으면 리서치 화면에 SEC 재무제표와 지표가 나오지 않습니다. 가격, 랭킹, 뉴스는 그대로 작동합니다.

### 2.3 Anthropic API 키 (AI 채팅용)
채팅은 Claude API를 사용합니다. **Claude Pro나 Max 구독에는 API 사용이 포함되지 않습니다.** API 사용료는 Anthropic Console 계정의 선불 크레딧으로 따로 결제됩니다.
1. https://console.anthropic.com/ 에 로그인합니다(claude.ai와 같은 계정이어도 됩니다).
2. **Billing**에서 크레딧을 구매합니다. 원하면 이중 안전장치로 그곳에 사용 한도도 설정하세요. 대시보드에도 자체 예산이 있습니다(6.5절).
3. **API Keys**에서 키를 만들고 복사합니다. `sk-ant-`로 시작합니다.
4. 다음 단계에서 `.env`에 넣습니다. 키가 없으면 채팅에 "키 없음"이 표시되고 아무 호출도 하지 않습니다.

### 2.4 `.env` 채우기
1. 프로젝트 폴더에서 `env.example`을 복사하고, 복사본 이름을 `.env`로 바꿉니다.
   (파일 탐색기: `env.example` 선택 → Ctrl+C → Ctrl+V → 복사본(`env - 복사본.example`)의 이름을 `.env`로 변경)
2. 메모장으로 `.env`를 열고 각 값을 `=` 뒤에 넣습니다. 공백이나 따옴표는 넣지 마세요.
   ```
   TOSS_CLIENT_ID=내-client-id
   TOSS_CLIENT_SECRET=내-client-secret
   FRED_API_KEY=내-fred-키
   ANTHROPIC_API_KEY=내-anthropic-키
   FINNHUB_API_KEY=내-finnhub-키
   ```
   `env.example`에 `ANTHROPIC_API_KEY=` 줄이 아직 없다면 그 줄(이름만, 값 없이)을 `env.example`에도 추가하세요.
3. 저장하고 닫습니다. 이 값들을 채팅, 이슈, 스크린샷에 절대 붙여 넣지 마세요.

## 3. 내 거래 기록과 평단가 (`data/positions.json`)

앱이 쓰는 파일(거래 기록, 저장된 라인, 설정 페이지 값, 관심 폴더, 내려받은 데이터)은 `data` 폴더에 있습니다.

손익 패널과 평단가 라인은 `data/positions.json`에 직접 입력한 거래 기록으로 계산합니다.
1. `data` 폴더에서 `positions.example.json`을 복사하고, 복사본 이름을 `positions.json`으로 바꿉니다.
2. 예시 거래를 내 거래로 바꿉니다: `time`(UTC 오프셋 필수, 예: `+09:00`), `symbol`, `side`(`buy`/`sell`), `qty`, `price`, `currency`(`USD`/`KRW`).
   `fee`와 `fx_rate`(실제로 적용된 1달러당 원화 환율)는 선택입니다. 수수료를 비워 두면 추정값으로 계산되고 **추정**으로 표시됩니다.
3. 선택: `avg_override`로 평단가를 직접 정할 수 있습니다. 계산된 값 대신 쓰이고 **입력**으로 표시됩니다.
4. 매수·매도 예정가("계획")는 여기에 입력하거나 화면에서 추가할 수 있습니다(5절).

파일에 JSON 오류가 있으면 화면에 줄과 칸 번호가 표시됩니다. 파일이 깨진 동안에는 절대 덮어쓰지 않습니다.
`positions.json`은 `.gitignore`에 들어 있어 내 컴퓨터에만 남습니다.
이 파일들이 `data`로 옮겨지기 전(2026-11-21)부터 앱을 썼다면, 다음에 백엔드가 시작될 때 예전 파일을 알아서 `data`로 옮깁니다. `data`에 이미 있는 파일은 절대 덮어쓰지 않습니다.

## 4. 실행과 종료

- **처음 한 번만:** **`scripts\set_passcode.cmd`**를 더블클릭하고 **로그인 암호**(8자 이상)와 **주문 PIN**(숫자 4~8자리)을 정합니다. 그 창에 입력하며 화면에 보이지 않고, 뒤섞인 해시만 저장됩니다 (`secrets\login.json`). 바꾸고 싶으면 언제든 다시 실행하세요.
- **실행:** **`scripts\start.cmd`**를 더블클릭합니다. 화면을 빌드한 뒤(몇 초) `http://127.0.0.1:8000`에서 대시보드를 실행합니다 (Toss, yfinance, FRED, Finnhub, Claude와 통신하고 키를 보관).
- **열기:** 브라우저에서 **http://127.0.0.1:8000** 으로 접속해 암호로 로그인합니다. 이 컴퓨터는 30일간 로그인이 유지됩니다.
- **종료:** `scripts\start.cmd` 창을 클릭하고 **Ctrl+C**를 누른 뒤(물어보면 `Y`), 창을 닫습니다.

"Port 8000 is already in use"가 나오면 대시보드가 이미 다른 창에서 실행 중일 가능성이 높습니다. 그 창을 쓰거나 먼저 닫으세요.

## 5. 화면 사용법

**화면 전환:** 위쪽 버튼으로 **데스크**(차트, 손익, 채팅, 호가, 뉴스), **리서치**(아래 "리서치 화면"), **주문**(7절), **매매일지**, **⚙ 설정**을 오갑니다. 마지막으로 본 화면과 종목은 기억됩니다.

**종목 이름을 누르면**(시장 정보 띠 칸, 손익, 미체결·예약 주문, 주문 화면 표, 규칙, 매매일지, 일정 목록, 시나리오 제목, 채팅 답변 속 종목) 그 종목이 현재 종목이 되고 리서치 화면이 열립니다.

**언어:** 대시보드를 처음 열면 **English** 또는 **한국어**를 고릅니다. 오른쪽 위 버튼으로 언제든 바꿀 수 있고, 선택은 브라우저에 저장됩니다. 한국어를 고르면 AI도 한국어로 답합니다(`vwap_5m` 같은 레벨 id, `USD`, `KST`는 그대로). 한국어 답변은 영어보다 토큰을 더 쓰기 때문에 메시지당 비용이 조금 더 듭니다.

| 영역 | 보여 주는 것 |
|---|---|
| 노란 띠 (맨 위) | 문제가 있을 때만 나타납니다: 키 미설정, Toss IP 미등록, 데이터 갱신 멈춤이나 오류 |
| 시장 정보 띠 | USD/KRW(Toss 참고 환율), 나스닥·S&P 선물(NQ, ES), ICESEMI, VIX, 미국 10년물(FRED 일별 + ^TNX 장중), **고정한 관심 폴더**의 처음 8개 종목(Toss 시세), **다음 일정** 칸(아래). 칸마다 출처와 지연(예: "yfinance · 약 15분 지연"), 마지막 업데이트 시각이 표시됩니다. 주황색은 **갱신 멈춤**, 빨간색은 **오류**입니다. 칸에 마우스를 올리면 자세한 내용이 나옵니다 |
| 차트 | 빠른 버튼(고정한 관심 폴더의 처음 12개 종목)을 누르거나 검색창에 미국 종목을 입력합니다. **1m / 5m / 일봉.** 오른쪽 위: **화면 고가 / 화면 저가**: 화면에 보이는 봉 중 가장 높은·낮은 가격과 현재가가 각각에서 몇 % 떨어져 있는지 (스크롤·확대에 따라 바뀜). **차트 아래** 체크박스: EMA 9/20/60, VWAP, RSI(봉 아래 작은 칸에 RSI 14, 30 / 70 기준선, 현재 값은 범례에 표시), 피보나치, 스윙(스윙 고점·저점 화살표), 내 라인, AI 라인, 주문(내 체결과 미체결 주문, 7.4절), 옵션 밴드(6.7절), 세션(음영: 보라 = 주간거래, 파랑 = 프리마켓, 음영 없음 = 정규장, 주황 = 애프터마켓), 거래량. 오른쪽 현재가 라벨에 지금 봉이 얼마나 진행됐는지 표시됩니다(예: 1분봉 `37/60s`, 5분봉 `2:37/5:00`, 최신 봉이 끝났으면 `마감`). 가장 최근 봉은 Toss 최신 시세로 약 2초마다 움직이고, EMA, VWAP, RSI는 완성된 봉으로만 계산합니다. 처음에 어떤 체크박스를 켤지는 설정 페이지에서 정합니다 |
| 피보나치 지정 | **피보나치 지정**을 누르고 봉 두 개를 클릭합니다. 클릭할 때마다 그 봉의 고가나 저가에 맞춰집니다. 레벨은 백엔드가 계산하고, 그 종목의 피보나치로 저장됩니다. 차트 아래 "저장된 라인"에서 삭제할 수 있습니다 |

| 내 계획 | 현재 종목의 매수·매도 예정가를 **USD 또는 KRW**로 추가합니다(통화는 꼭 골라야 함). `positions.json`에 저장되고 초록(매수)·빨강(매도) 라인으로 그려집니다. 원화 가격은 옆에 표시된 Toss 참고 환율로 환산합니다. 평단가는 주황 라인으로 그려집니다 |
| 채팅 | AI 채팅 (6절) |
| 호가창 | 차트 종목의 실시간 매도/매수 호가 (Toss 실시간, 모든 미국 주식·ETF). 빨간 줄 = 매도호가, 초록 줄 = 매수호가, 막대 = 잔량. 가운데 줄은 **스프레드**(최우선 매도호가 − 최우선 매수호가, USD와 가격 대비 %)이며, `spread.warn_pct`(0.20%)보다 넓으면 **주황색**이 됩니다(시장가 주문이 불리한 가격에 체결될 수 있다는 뜻). 맨 위에 세션(주간/프리/정규/애프터), Toss가 준 호가 단수, 연결 상태가 나옵니다: **실시간**, 또는 "연결 끊김, N초 후 재시도 · 2초마다 조회 중"(스스로 다시 연결하고, 그동안은 조회로 계속 작동). 아래는 최근 체결(초록 = 상승 체결, 빨강 = 하락 체결) |
| 뉴스 | 화면에 띄운 종목, 보유 종목, 관련 종목(`config.yaml`의 `news.related`), `news.extra`의 뉴스를 코드가 Finnhub에서 가져옵니다. 항목마다 제목(링크), 출처, KST 시각(또는 **날짜 미확인**), 종목, AI 분류: 중요도 **높음**(빨강) / **중간**(주황) / **낮음**(회색), 내 보유 종목에 대한 영향(**유리** 초록 / **불리** 빨강 / 불분명), 한 줄 이유. 중복은 합치고 48시간 지난 뉴스는 숨깁니다. 전체 / 이 종목, 중요도로 걸러 볼 수 있습니다 |

- 모든 시각은 한국 시간(KST)입니다. 분봉은 봉의 **시작** 시각으로, 일봉은 미국 거래일로 표시합니다.

### 리서치 화면

위쪽 **리서치**를 누릅니다. 왼쪽은 **탐색** 패널, 가운데는 저장한 **투자 논리**와 현재 종목의 **기업 화면**, 오른쪽은 **리서치 채팅**입니다(좁은 화면에서는 기업 화면 아래, 휴대폰에서는 위쪽 **탐색 / 기업 / 채팅**으로 전환). **데스크에서 열기 →**를 누르면 그 종목이 차트로 갑니다.

**탐색 패널** (탭 3개):
- **랭킹**: Toss 랭킹 상위 100: 거래량, 거래대금, 급상승, 급하락, 토스 인기(토스 체결만), 기간은 실시간 / 1일 / 1주 / 1개월 / 3개월 / 6개월 / 1년(급상승·급하락은 실시간 없음). 등락은 전일 종가 대비, 급상승·급하락은 기간 시작 대비입니다. 거래량 랭킹은 대부분 ETF입니다.
- **섹터**: Toss 자체 섹터 분류(상위 섹터 또는 전체). 섹터를 누르면 시가총액순 종목과 관련 ETF가 나옵니다. 금액은 원화(Toss가 미국 주식도 환산), 시가총액은 하루 한 번 갱신, Toss가 섹터 목록에 등락률을 주지 않아 상위 종목만 가격을 따로 가져옵니다.
- **관심**: 관심 폴더(`data/watchlist.json`에 저장). **+ 폴더**, 이름 바꾸기, 삭제, **고정**. 고정한 폴더가 차트 빠른 버튼과 시장 정보 띠의 처음 8개 종목 칸이 되고, 그 종목들은 뉴스 피드에도 들어갑니다. 종목 옆 **★** 또는 검색창으로 추가·삭제합니다. 최대 20개 폴더 × 100종목.

**기업 화면** (위쪽 검색창에서 아무 미국 종목이나 검색 가능, 폴더에 넣을 필요 없음):

| 탭 | 내용 | 출처 |
|---|---|---|
| 개요 | 시가총액, 기업가치(EV), P/E, P/S, P/B, EV/EBIT, FCF 수익률, 성장(매출 전년 대비·3 / 5년 연평균, EPS 전년 대비), 이익률, ROE, 순부채, 잉여현금흐름, 주식 수 변화, 자기 과거·동종 기업 P/E 중앙값과 그에 해당하는 가격, 애널리스트 목표가, 다음 실적 발표 | SEC 수치와 Toss 실시간 가격으로 코드가 계산 |
| 재무 | 손익계산서, 재무상태표, 현금흐름표: 5년(연간) 또는 8분기(분기) + 최근 4분기 합(TTM). `*` = 보고된 수치에서 코드로 계산(마우스를 올리면 출처), `—` = 보고 안 됨 | SEC EDGAR (SEC에 없으면 yfinance, 비공식 표시) |

| 애널리스트 | 의견 분포(적극 매수 … 적극 매도), 목표가(최저 / 중앙 / 평균 / 최고 vs 현재가) | Finnhub, yfinance |

- ETF는 기업 재무가 없어서 Toss 기본 정보를 대신 보여 줍니다.
- 모든 값에 출처가 붙고, 비공식(yfinance) 값은 따로 표시됩니다. 이 숫자들은 AI가 만들지 않습니다.

**리서치 채팅** (종목마다 따로 있는 채팅, 데스크 채팅과 별개):
- 기업에 대해 물어보세요: "싼가요?", 성장, 이익률, 실적, 동종 기업, 뉴스. AI는 코드가 계산한 숫자(기업 화면 값과 그 id)만 인용하고, 근거를 찾을 수 없는 숫자는 답변 아래 "확인 안 된 숫자"로 표시됩니다.
- **밸류에이션** 버튼(또는 질문): **밸류에이션 카드**. 세 가지 기준(과거 대비, 동종 대비, 성장 대비: 저평가 / 적정 / 고평가 / 판단 불가)의 판단, 근거 값, 위험 요인, 판단이 바뀔 조건, 기준 가격(과거 중앙 P/E 기준 가격, 애널리스트 목표가)과 출처·시각. "판단 불가"는 그 기준의 데이터가 없다는 뜻입니다.
- 종목 찾기: 오늘 거래가 많은 종목, 급상승 종목, 섹터 대표 종목, 이름 검색을 요청하면 추천 종목이 버튼으로 나오고 누르면 그 종목이 열립니다. 살펴볼 후보일 뿐 매매 추천이 아닙니다.
- 리서치 채팅에는 **주문 기능이 없습니다**. 매매하려면 **데스크에서 열기**를 누르세요.

**투자 논리** (종목당 하나, 기록 보관, `logs/research/research.sqlite`에 저장):
- 밸류에이션 카드의 **투자 논리 저장**: 요약(최대 400자)을 고치고, 데스크 차트에 표시할 기준 가격을 고를 수 있습니다. AI는 내 메시지가 저장을 요청할 때만("저장해줘", "save it"), 그리고 숫자가 확인된 카드만 저장합니다.
- 투자 논리 카드(기업 화면 위)에 판단, 저장 시 가격과 그 뒤 변동, 저장 후 새 SEC 공시 경고, 실적 발표까지 남은 날이 나옵니다. **수정**, **삭제**, **기록**.
- **데스크**에서: 내 정보 위에 짧은 투자 논리 카드(**리서치에서 열기**), 고른 기준 가격이 차트에 보라색 점선 **투자 논리 라인**으로 표시(차트 토글 따로 있음). 데스크 AI도 투자 논리를 보고 그 가격(id `thesis_...`)을 인용할 수 있습니다. 주문 규칙은 그대로입니다.

**메모** (투자 논리 아래): 직접 쓰는 날짜별 짧은 메모(최대 300자). 앱이 확실히 아는 사실("직접 저장한 투자 논리…")도 기록합니다. 두 채팅 모두 투자 논리와 메모를 봅니다. AI는 메모를 쓰지 않습니다.

## 6. AI 채팅

종목마다 채팅이 따로 있습니다(데스크와 리서치도 각각). 종목을 열면 그 종목의 채팅과 마지막으로 열어 둔 채팅이 나오고, **새 채팅**은 그 종목의 채팅을 하나 더 만듭니다. 채팅은 자기 종목에 묶여 있어서, 다른 종목을 물으려면 그 종목을 여세요. 답변 중에 종목을 바꿔도 답변은 계속되고 원래 채팅에 저장됩니다.

### 6.1 질문하기
- 질문을 입력하고 **Enter**를 누릅니다(줄바꿈은 **Shift+Enter**). 답변은 작성되는 대로 나타납니다.
- 채팅은 지금 차트에 어떤 종목과 시간 단위가 떠 있는지, 어떤 라인이 보이는지 알고 있습니다.
- 예시: "SOXS 5분봉 지지선은 어디야?", "최근 스윙 저점 두 개로 추세선 그려 줘", "최근 스윙 고점에서 스윙 저점까지 피보나치 다시 그려 줘", "SOXS 시나리오 줘".
- **뉴스:** "NVDA 중요한 뉴스 있어?"처럼 물으면 채팅이 뉴스 피드를 검색해 링크, 날짜, AI 분류와 함께 답합니다. 시나리오 표의 "비용 차감 후"에는 이제 현재 호가 스프레드도 포함됩니다.
- **가격은 대시보드가 직접 계산한 값**(EMA, VWAP, 피보나치, 스윙, 전일 가격, 내 평단가와 계획)이나 내가 입력한 숫자에서만 나옵니다.
  - AI는 가격마다 레벨 id를 붙입니다. 예: `4.12 (vwap_5m)`.
  - AI가 그리는 라인은 코드로 검사합니다. 계산된 레벨이 아닌 가격은 거부되고, AI가 고쳐야 합니다.
  - 대시보드 데이터에 없는 숫자가 답변에 있으면 메시지에 **"대시보드 데이터에 없는 숫자"** 경고가 붙습니다.
- **그리기:** AI 라인은 차트에 바로 나타납니다(하늘색, "AI" 표시). **AI 라인** 표시 선택으로 내 라인과 따로 숨기거나 보일 수 있습니다. AI는 자기가 그린 라인만 지울 수 있습니다.
- **시나리오:** 시나리오를 물으면 실제 표가 나옵니다: 방향, 진입, 무효화, 목표, 손익비, 비용 차감 후 움직임(추정), 그리고 각 가격의 근거 레벨.
  - 손익비와 비용 차감 후 움직임은 코드가 계산합니다: 양쪽 0.1% 수수료 + 환전 스프레드 추정치.
  - 행을 눌러도 아무것도 전송되지 않습니다. 시나리오 카드의 버튼은 주문 양식만 채웁니다(7.3절).
- **채팅 기록**은 내 컴퓨터의 `logs/chat/chat.sqlite`에 저장됩니다. 드롭다운으로 채팅을 바꾸고, **새 채팅**으로 시작하고, **삭제**로 지웁니다.
- **긴 채팅:** 약 6만 토큰을 넘으면 Claude Haiku가 오래된 부분을 요약합니다. 요약된 메시지는 흐리게 표시됩니다.

### 6.2 모델 선택
| 버튼 | 모델 | 용도 |
|---|---|---|
| **일반** (기본) | Claude Sonnet 5.5 | 평소 질문, 라인, 시나리오 |
| **심층** | Claude Opus 5.5 | 중요한 진입·청산 판단 (비용 약 2배) |
| **최심층** | Claude Fable 5.2 | 실적 발표 전후 같은 큰 판단 (비용 약 4배) |

긴 채팅의 요약은 백그라운드에서 Claude Haiku 5.5가 합니다.
**팁:** 긴 채팅 중간에 모델을 바꾸면 새 모델이 채팅 전체를 처음부터 캐시해야 해서 비쌉니다. 심층·최심층으로 물을 때는 **새 채팅**에서 시작하면 훨씬 저렴합니다.
모델 ID와 가격은 `config.yaml`(`llm:`)에 있습니다. ID가 맞는지 확인하려면 **`scripts\check_models.cmd`**를 더블클릭하세요. 무료이며 토큰을 쓰지 않습니다.

모델의 안전 필터가 질문을 거절하면 Anthropic이 자동으로 대체 모델로 다시 시도합니다(`config.yaml`의 `refusal_fallback`). 그때 비용 줄에는 실제로 답한 모델이 표시됩니다.

### 6.3 웹 검색
채팅의 **웹 검색** 체크박스를 켜면 그 메시지에 Claude 웹 검색을 씁니다. 기본값은 꺼짐입니다.
- 검색 1,000회당 USD 10, 그리고 검색 결과 텍스트(입력 토큰으로 과금)가 듭니다. 메시지당 최대 3회(`config.yaml`).
- 결과는 참고용이며 링크와 날짜를 붙입니다. 가격과 레벨은 절대 웹에서 가져오지 않습니다.
- 켜고 끌 때마다 요청 내용이 바뀌어서, 다음 메시지에서 캐시를 한 번 다시 만듭니다(그 메시지만 조금 비쌈).

### 6.4 비용 줄 읽는 법 (모든 답변 아래)
`Sonnet 5.5 · 입력 310 · 출력 52 · 캐시 저장 2,000 / 읽기 2,000 · 적중 46% · USD 0.0093 · KRW 13 (1 USD = 1,375.00 KRW, Toss 참고 환율 09:30:00 KST)`
- **입력:** 정가로 과금되는 새 입력 토큰.
- **출력:** 답변 토큰(모델이 생각하는 데 쓴 토큰 포함).
- **캐시 저장 / 읽기:** Anthropic 프롬프트 캐시에 저장하거나 다시 쓴 토큰. 읽기는 일반 입력 가격의 1/20, 저장은 1.25배(1시간 저장은 2배)입니다.
- **적중:** 프롬프트 중 캐시에서 나온 비율. 이어지는 채팅에서는 높습니다. 모델을 바꾸거나 웹 검색을 켜고 끈 직후 메시지에서는 낮아집니다(모델마다 캐시가 따로 있음).
- **USD / KRW:** 토큰 수와 `config.yaml`의 가격으로 계산한 정확한 비용을, 그 시점의 Toss 참고 환율로 환산한 값입니다.

모든 API 호출은 `logs/usage.jsonl`에도 기록됩니다: 시각, 모델, 토큰, 비용, 환율. 메시지 내용과 키는 절대 기록하지 않습니다.

### 6.5 예산
- 채팅 위 헤더에 **오늘**과 **이번 달** 사용액(KST 기준 날짜·월), 한도, 모델별 비율이 표시됩니다.
- 한도는 `config.yaml`의 `budget:`에 있습니다(현재 하루 USD 5, 한 달 USD 100).
- **80%**가 되면 헤더가 주황색으로 바뀝니다.
- **100%**가 되면 심층·최심층은 막히고, 일반은 메시지마다 확인을 받습니다.
- AI 크레딧은 **손익** 패널에도 나오고 **순손익**에서 빠집니다.

### 6.6 원본 캔들과 A/B 테스트
채팅은 이제 레벨과 함께 **원본 캔들**도 AI에게 보냅니다(`config.yaml`의 `llm.candles.mode: B`, 2026-11-17 선택). 프리마켓 시작 이후의 모든 5분봉(메시지마다 새로 생긴 봉만)과 최근 1분봉 60개입니다. 레벨만 보내려면 `mode: A`로 바꾸세요. 아래 A/B 테스트로 두 방식을 비교할 수 있습니다(선택).
1. 대시보드를 닫습니다(테스트가 자체 Toss 연결을 엽니다).
2. **`scripts\ab_test.cmd`**를 더블클릭합니다. **무료**로 비용 추정치를 보여 주고, `YES`를 입력해야만 비용을 씁니다.
3. 질문 15개(`backend/ab/questions.yaml`)를 두 번씩 물어봅니다.
   - A = 레벨만
   - B = 레벨 + 원본 캔들
4. 답변의 모든 가격을 대시보드 데이터와 대조합니다.
5. 보고서는 `logs/ab/ab_<날짜>.md`에 저장됩니다. A나 B를 고른 뒤 `config.yaml`의 `llm.candles.mode`를 설정하세요.

(`.cmd` 창의 안내 문구는 영어입니다. Windows 명령 창은 한글이 깨질 수 있기 때문입니다.)

### 6.7 빠른 분석 버튼과 옵션 데이터

**⚡ 전체 분석** (보내기 옆)을 누르면 화면 종목에 대한 저장된 요청이 보내집니다: 1분봉·5분봉 기술적 분석, 뉴스,
옵션 예상 변동폭, 매수 / 관망 / 매도 결론, 수량이 들어간 시나리오 표, 규칙 또는 주문 초안. 규칙은 제안까지만 하므로,
활성화하려면 이어서 "걸어줘"라고 하세요. 문구는 **설정 → AI → 빠른 분석 요청**에서 바꿀 수 있습니다 (비우면 기본 문구).

데스크의 **옵션 (내재)** 패널 (휴대폰: 호가 탭)과 차트 토글 **옵션 범위**:

- **예상 변동폭**: 옵션 시장이 가격에 반영한 일반적인 움직임의 크기 (1 시그마, 약 68 %의 경우). 오늘, 그리고 다음
  주간 / 월간 만기까지의 가격 범위를 보여줍니다. **방향이 아니라 크기**입니다.
- **yfinance 옵션 체인 (~15분 지연)**으로 코드에서 계산합니다. 미국 정규장 밖에서는 **지난 거래일** 값입니다 (표시됨).
  IV는 ATM 스트래들에서 구하고, Yahoo 자체 IV는 참고용으로만 보여줍니다.
- **품질**: 호가 차이로 판단. "얇음" = 호가 차이가 너무 커서 그 종목은 예상 변동폭을 표시하지 않습니다 (2026-11-21 SOXX).
- 그 밖에: IV / 최근 20일 실제 변동, 기간 구조 ("역전" = 곧 이벤트 예상), 풋/콜 가격, 풋/콜 거래량, 거래 많은 행사가.
  미결제약정은 **사용하지 않습니다** (Yahoo 값이 확인에서 틀림).
- AI 채팅은 매 메시지마다 요약을 보고, 필요하면 자세한 값을 요청합니다 (`get_options`). 범위는 레벨
  `em_day_up` / `em_day_down` (주간 / 월간도)로, AI가 인용하고 그리고 시나리오에 쓸 수 있습니다.

## 7. 주문 (4단계)

### 7.1 안전 먼저: 모의 주문(DRY RUN)
- **기본값은 모의 주문(DRY RUN)입니다** (`config.yaml` → `orders:` → `dry_run: true`). 주문 탭 위에 파란 줄이 보입니다: *"모의 주문(DRY RUN): 주문은 시뮬레이션만 됩니다. Toss로 아무것도 보내지 않습니다."*
- DRY RUN 중에는 백엔드가 **토스 주문 주소를 절대 호출하지 않습니다**. 코드에서 꺼져 있어서 무언가가 요청해도 거절합니다. "전송"은 내 컴퓨터에서만 시뮬레이션됩니다.
  - 주문 탭의 **모의 주문** 목록에 나타나고, 실제 주문처럼 정정·취소할 수 있습니다.
  - 차트에 점선 **DRY RUN** 라인으로 표시됩니다.
  - 체결되지 않으므로 손익이나 매매일지에는 나오지 않습니다.
- 모든 주문은 **초안 → 내가 승인 → 전송**입니다. 한 번 눌러서 나가는 주문은 없습니다. AI는 초안만 만들 수 있고, 보낼 방법이 없습니다.
- 모든 전송 요청과 결과는 `logs/trades.jsonl`에 기록됩니다 (키는 기록하지 않음).

### 7.2 주문하기 (주문 탭)
1. **종목:** 고릅니다 (티커나 이름으로 검색). 옆에 실시간 매수·매도 호가, 스프레드, 현재가가 보입니다.
2. **종류:**
   - **매수** 또는 **매도**
   - **예약 매수 / 예약 매도**: 가격이 감시가에 닿으면 자동으로 주문되며, 만료일(최대 1년)까지 유효합니다.
   - **OCO**: 보유 주식에 매도 두 개를 겁니다. 위(익절)와 아래(손절) 중 먼저 닿은 쪽이 매도되고 나머지는 취소됩니다.
   - **OTO**: 매수가 체결되면 매도가 자동으로 들어갑니다.
   - "예약" 주문은 토스의 *조건부 주문*입니다.
3. **주문 방식:** 지정가 또는 시장가. **현재가** 버튼은 최근 체결가를 가격 칸에 넣어서, 승인 전에 확인할 수 있게 합니다.
4. **수량:** 주식 수, 주문가능금액의 %(매수), 보유 수량의 %(매도), 또는 USD 금액(시장가만). %와 금액은 코드가 주식 수로 바꿔서 승인 전에 보여줍니다.
5. **유효기간:** 일반 주문은 *당일* 또는 *종가까지*. 예약 주문은 대신 만료일이 필요합니다.
6. **초안 만들기.** 코드가 모든 것을 확인합니다 (7.6). 초안은 기본 3분간 유효합니다.
7. **검토 후 승인.** 승인 화면에 한 문장 요약, 모든 값, 예상 비용이 나옵니다. 승인을 누르면 **최신 가격으로 모든 확인을 다시 한 뒤** 전송합니다 (DRY RUN이면 시뮬레이션).

- **한 번만 전송:** 초안 하나는 한 번만 보낼 수 있습니다. 토스에 초안 ID를 `clientOrderId`로 보내므로, 연결이 끊겨 자동으로 다시 보내도 두 번 주문되지 않습니다.
- **정정·취소:** 미체결 주문은 **가격 정정 / 취소**, 예약 주문은 **수정 / 취소**를 누릅니다. 초안을 만들고 같은 승인 단계를 거칩니다.
  - 미국 주식 주문은 **가격만** 바꿀 수 있고 수량은 안 됩니다.
  - 정정·취소는 **자동으로 다시 보내지 않습니다**. 결과가 *unknown*이면 다시 시도하기 전에 토스에서 미체결 주문을 확인하세요.
- **설정:** ⚙ 설정 페이지에서 **가격 범위 ±%**(지정가가 현재가에서 이만큼 안에 있어야 함)와 **초안 유효시간**을 정합니다.

### 7.3 채팅에서 주문하기
- **시나리오 카드:** 각 카드에 가격이 적힌 단순 버튼이 있습니다: *매수 · 지정가 …*, *예약 매수 · … 도달 시*(롱), 또는 *매도 · 지정가 …*, *예약 매도 · … 도달 시*(숏).
  - **함께 주문:** AI가 진입과 익절/손절을 하나의 계획으로 추천할 때만 묶음 버튼이 나옵니다: *매수 후 익절 매도 (OTO)*, *익절 + 손절 (OCO)*.
  - 이미 보유한 주식을 지키는 경우에는 *익절 매도*, *손절 예약 매도*, *익절 + 손절 (OCO)*가 나옵니다.
  - 버튼은 **주문서만 채우고**, 가격은 토스 호가 단위로 반올림합니다. 초안을 만들거나 보내지 않습니다.
  - 수량(예약 주문은 만료일도)을 입력하고 **초안 만들기**, **검토 후 승인**을 누릅니다.
  - 주문 탭 위쪽에도 최근 시나리오가 보입니다.
- **채팅에 주문 입력** (예: *"SOXS 10주 4.25 지정가 당일 매수"*):
  - 쓰는 숫자가 전부 내 메시지에 있고 *당일* 또는 *종가까지*(예약 주문은 만료일)를 말했을 때만 AI가 **초안**을 만듭니다.
  - 빠진 것은 물어봅니다. 숫자를 스스로 채우거나 전송하지 않습니다.
  - 초안이 만들어지면 **주문 탭 열기** 버튼이 있는 안내가 나옵니다.

### 7.4 매매일지, 손익, 차트
- **매매일지:** 위쪽 버튼.
  - **이 프로그램으로 한** 거래만 보여줍니다. 거래 하나 = 0주에서 보유했다가 다시 0주가 될 때까지.
  - 그중 주문이 하나라도 여기서 나갔으면 표시하고, 판 주식의 이전 매수도 포함합니다.
  - 카드마다 진입 → 청산(KST), 보유 시간, 평균 가격, 실현·미실현 손익, 수수료, 환전 비용(추정), 보유 기간 중 쓴 AI 크레딧, 순손익이 나옵니다.
  - AI 크레딧은 시간 기준입니다 (사용 기록에 어떤 종목을 물었는지 없음). 합계는 호출마다 한 번만 셉니다.
  - DRY RUN 중에는 모의 주문이 체결되지 않으므로 매매일지가 비어 있습니다.
- **손익:** 토스 체결 내역과 보유 종목으로 계산합니다.
  - **오늘** = 오늘 거래.
  - **보유 종목** = 지금 보유한 종목만, 각 종목을 0주에서 마지막으로 산 시점부터.
- **차트 "주문" 체크박스:**
  - 실제 체결은 체결된 봉에 **B / S** 표시로 나옵니다.
  - 미체결 주문, 예약 주문 감시가, DRY RUN 모의 주문은 점선으로 나옵니다.

### 7.5 실제 주문: 켜기, 그리고 다시 모의 주문으로
**이 작업은 본인만 합니다. Claude는 바꾸지 않고, 설정 페이지에서도 바꿀 수 없습니다 (일부러).** 토스에는 테스트 환경이 없습니다: DRY RUN을 끄면 승인한 주문은 실제 돈입니다.

켜기 전에 DRY RUN 상태에서 4단계 확인 목록(9절)을 해 보세요.

**실제 주문으로 바꾸기**
1. 대시보드 종료: `scripts\start.cmd` 창을 클릭하고 **Ctrl+C**.
2. **`config.yaml`**을 메모장으로 엽니다. `orders:` 부분에서 `dry_run: true`를 **`dry_run: false`**로 바꾸고 저장합니다.
3. `scripts\start.cmd`를 다시 실행합니다. 창에 **"REAL ORDERS ARE ON"**이 나오고, 주문 탭에서는:
   - 줄이 빨간색이 됩니다: *"실제 주문: 승인한 주문이 Toss로 전송됩니다."*
   - 승인 버튼이 **"승인 및 실제 주문 전송"**으로 바뀝니다.
4. 작게 시작하세요: 예를 들어 현재가보다 한참 낮은 1주 지정가 매수를 넣고 취소해 봅니다. 토스 앱에서도 확인하세요.
   - 토스가 모든 실제 주문을 권한·접근 문제로 거절하면, 토스 개발자 사이트에서 API 키 설정을 확인하세요.

**다시 모의 주문(DRY RUN)으로**
1. 대시보드 종료 (Ctrl+C).
2. `config.yaml`에서 `dry_run: true`로 바꾸고 저장.
3. 다시 실행하고 주문 탭의 줄이 다시 **파란색**(DRY RUN)인지 확인합니다.

이미 토스로 보낸 주문은 다시 바꿔도 토스에 남아 있습니다. 토스 앱에서 정정·취소하세요.

### 7.8 자동 규칙

규칙은 "가격이 이렇게 되면 이 주문을 보낸다"입니다. **활성화를 누르기 전까지는 아무 일도 하지 않습니다.**
활성화하면 조건이 충족되는 순간 앱이 직접 주문을 보냅니다. 추가 승인은 없습니다.

**위치:** 주문 화면의 **자동 규칙** 표 ("채팅에서" 아래; 휴대폰: 주문 탭). 활성화된 규칙은 데스크 차트에 선으로 계속 표시됩니다.

**규칙 유형**

| 유형 | 실행 조건 | 쓰임새 |
|---|---|---|
| 도달 후 되돌림 | 가격이 X 이상에 닿은 뒤 N분 안에 Y 이하로 내려옴 | 저항에서 밀릴 때 익절 |
| 도달 후 반등 | 가격이 X 이하에 닿은 뒤 N분 안에 Y 이상으로 올라옴 | 지지가 버틸 때 매수 |
| 봉 마감 돌파 | 1분 / 5분봉이 Y 이상(또는 이하)으로 마감 | 돌파 / 이탈 |

**확인 방식:** *체결가*는 Y에서 첫 체결이 나오면 실행됩니다. *1분 / 5분봉 마감*은 봉이 끝날 때까지 기다렸다가
종가를 봅니다. 잠깐 찍고 돌아오는 꼬리는 무시되므로, 일시적인 튐인지 실제 움직임인지 가릴 때 씁니다.
도달 후 제한 시간이 지나면 규칙은 다시 도달을 기다립니다 (활성 상태 유지).

단순히 "가격이 Y에 도달하면"은 Toss 예약 주문을 쓰세요. 앱이 꺼져 있어도 Toss 서버에서 실행됩니다.
규칙 편집기는 이 경우를 거부하고 안내합니다.

**사용법**
1. **새 규칙**을 누르고 채운 뒤 **규칙 저장 (비활성)**. 또는 AI 채팅에 제안을 요청하세요. **AI 제안** 표시와
   AI가 정한 값 목록이 함께 나옵니다.
2. **활성화**를 누르면 정확한 주문, DRY RUN / 실제 주문 표시, 문제점이 나옵니다. **규칙 활성화**를 누르세요.
3. 활성 중에는 상태가 보입니다 ("23:41에 4.30 USD 도달, 23:56까지 대기"). 차트에 노란 점선으로 표시됩니다.
4. **해제**는 규칙 하나를 멈춥니다. **모두 해제**는 전체 정지 버튼입니다.

**안전장치**
- 규칙은 활성화 버튼으로 켜거나, 채팅에서 AI에게 요청해 켤 수 있습니다 ("걸어줘", "활성화해줘", "arm them"). AI는 메시지에 그런 요청이 있을 때만 활성화할 수 있고 (코드에서 확인), 그런 규칙에는 **요청에 따라 AI가 활성화** 표시가 붙습니다. 대체되는 규칙은 AI가 해제 / 삭제해 같은 주식이 두 번 걸리지 않게 합니다.
- 한 번만 실행됩니다. 실행 시 수동 초안과 같은 검사를 현재가로 다시 합니다 (보유 수량, 주문가능금액, 가격 범위,
  종목) + 세션 ("정규장에서만" 규칙) + 선택 매수 한도 (설정 → 주문: "자동 규칙: 매수 1건당 주문가능금액 최대 %").
  검사에 걸리면 **차단됨**이 되고 아무것도 보내지 않으며, 다시 시도하지 않습니다.
- 오래된 데이터로는 실행하지 않습니다: 실시간 가격이 15초 끊기면 일시정지하고, 진행 중이던 도달은 지웁니다.
- **앱이 실행 중이어야 합니다.** 컴퓨터가 절전되거나 앱이 꺼지면 실행되지 않습니다. 재시작하면 활성 규칙은
  활성으로 돌아오지만 새 도달을 기다립니다.
- DRY RUN: 실행된 규칙은 모의 처리됩니다. `dry_run: false`이면 **실제** 주문이 나갑니다.
- 생성 / 활성화 / 도달 / 실행 / 결과 / 해제는 모두 `logs/trades.jsonl`에 기록됩니다. 규칙은 `logs/rules.json`에 저장됩니다.

**한도:** 활성 규칙 10개, 활성 규칙 종목 5개, 규칙 최대 30일 (`config.yaml`의 `rules:`: `enabled`, `max_armed`,
`max_proposed`, `stale_seconds`, `max_days`).

## 8. 휴대폰 접속 (5단계)

대시보드는 집 PC에서 계속 실행되고, **그 PC에서만** 연결을 받습니다. **Tailscale**(무료 사설 네트워크 앱)이 휴대폰을 암호화해서 연결해 주며, 내 계정으로 로그인한 내 기기만 들어올 수 있습니다. 키, 토스 호출, 모든 기록은 집 PC에 그대로 있고, 휴대폰은 화면만 보여 줍니다.

> ⛔ **`tailscale funnel`은 절대 실행하지 마세요.** 공유기 포트 포워딩도 하지 마세요. Funnel은 서비스를 공개 인터넷에 올립니다. 대시보드도 내 Tailscale 기기에서 오지 않은 요청은 거절하지만, 그것만 믿지 마세요.

**휴대폰 접속은 기본으로 꺼져 있습니다** (`config.yaml`의 `remote.allow_remote: false`). 이 상태에서는 대시보드가 실행 중인 컴퓨터에서만 작동하고, 다른 기기의 요청은 모두 거절됩니다. 휴대폰을 쓰려면 `true`로 바꾸고 재시작한 뒤 아래 단계를 따르세요.

### 8.1 집 PC (처음 한 번)
1. 아직이면 암호와 PIN을 정합니다: `scripts\set_passcode.cmd` (4절).
2. https://tailscale.com/download 에서 **Windows용 Tailscale**을 설치하고 로그인합니다 (예: 구글 계정). 나중에 휴대폰에서도 같은 계정을 씁니다.
3. Tailscale 관리 콘솔의 **DNS** 페이지(https://console.tailscale.com/admin/dns)에서:
   - 꺼져 있으면 **MagicDNS**를 켭니다.
   - **HTTPS Certificates**에서 **Enable HTTPS**를 누릅니다.
   - 참고: 이렇게 하면 기기 이름이 공개 인증서 기록에 남습니다. PC 이름에 실명이 들어 있으면 먼저 **Machines** 페이지에서 이름을 바꾸세요 (예: `desk`).
4. `scripts\start.cmd`로 대시보드를 실행합니다.
5. **명령 프롬프트**를 열고(시작 메뉴 → `cmd` 입력) 다음을 실행합니다:
   ```
   tailscale serve --bg 8000
   ```
   `https://desk.tailXXXX.ts.net` 같은 주소가 나옵니다. 적어 두세요.
   - HTTPS를 켜라는 링크가 나오면 열어서 승인한 뒤 명령을 다시 실행하세요.
   - `--bg`는 백그라운드에서 계속 켜 두는 옵션이고, 재시작 후에도 Tailscale이 다시 켭니다.
   - 확인: `tailscale serve status`. 끄기: `tailscale serve --https=443 8000 off` (또는 serve 설정 전체를 지우는 `tailscale serve reset`).

### 8.2 휴대폰 (처음 한 번)
1. **Tailscale** 앱(App Store / Play 스토어)을 설치하고 **같은 계정**으로 로그인해 켭니다.
2. Safari(아이폰)나 Chrome(안드로이드)에서 `https://….ts.net` 주소를 열고 암호로 로그인합니다. 휴대폰 로그인은 24시간 유지됩니다 (`config.yaml`의 `remote.remote_session_hours`).
3. 홈 화면에 추가:
   - **아이폰(Safari):** 공유 버튼 → **홈 화면에 추가**.
   - **안드로이드(Chrome):** ⋮ 메뉴 → **앱 설치**(또는 **홈 화면에 추가**).

   그러면 앱처럼 전체 화면으로 열립니다. 휴대폰에는 시세나 계좌 데이터를 저장하지 않습니다.

### 8.3 회사 노트북 (회사가 허용하는 경우만)
휴대폰과 같습니다: Tailscale 설치, 같은 계정으로 로그인, 주소 열기. 회사 노트북에서는 VPN 앱을 허용하지 않거나 사내망에서 막는 경우가 많습니다. 그러면 휴대폰을 쓰세요.

### 8.4 휴대폰에서 되는 것
- **보는 것은 전부:** 차트, 손익, 채팅, 호가, 뉴스, 매매일지. 초안도 만들 수 있습니다.
- **휴대폰에서 주문 전송은 꺼져 있습니다.** 승인 화면에 그렇게 나오니 집 PC에서 승인하세요. PC에서 주문을 충분히 써 본 뒤 원하면 직접 켜세요:
  1. `config.yaml` → `remote:`에서 `orders_enabled: true`로 바꿉니다.
  2. 대시보드를 재시작합니다.

  그다음부터는:
  - 휴대폰에서 보낼 때마다 **PIN**을 묻습니다.
  - 승인 화면이 큰 글씨로 나옵니다.
  - 휴대폰에서는 **시장가 주문이 막힙니다** (`block_market_orders: true`).

  DRY RUN은 PC와 똑같이 적용됩니다.
- 암호나 PIN을 5번 틀리면 그 기기는 15분간 잠깁니다.
- 오른쪽 위 **로그아웃**은 그 기기의 로그인을 끝냅니다.
- 선택: `config.yaml`의 `remote.allowed_logins`에 내 Tailscale 계정을 적으면 다른 계정은 모두 거절합니다.

### 8.5 장중에 집 PC가 잠들지 않게
- **설정 → 시스템 → 전원 및 배터리 → 화면, 절전 및 최대 절전 모드 시간 제한:** "전원에 연결된 경우 절전 모드로 전환"을 **안 함**으로.
- **노트북:** 제어판 → 전원 옵션 → **덮개를 닫으면 수행되는 작업 선택** → *전원 연결: 아무 것도 안 함*.
- 업데이트로 Windows가 재시작되면 Tailscale serve는 저절로 다시 켜지지만, 대시보드는 아닙니다: `scripts\start.cmd`를 다시 실행하세요.
- PC에 연결할 수 없으면 휴대폰에 빨간 줄이 나옵니다: "집 PC와 연결이 끊겼습니다 … 마지막 업데이트 hh:mm:ss KST". 저절로 다시 연결합니다.

### 8.6 안 될 때
| 보이는 것 | 할 일 |
|---|---|
| 주소가 아예 안 열림 | 휴대폰과 PC 모두 Tailscale이 켜져 있나? 대시보드가 실행 중인가? `tailscale serve status`에 8000이 보이나? |
| "only your own Tailscale devices can open this" | 내 로그인 기기에서 온 요청이 아님 (예: Funnel). `funnel`이 아니라 `serve`를 쓰세요 |
| "집 PC와 연결이 끊겼습니다" | PC가 절전/꺼짐, 또는 대시보드가 멈춤 (8.5절) |
| "암호가 틀렸습니다 … 남음" / 잠김 | 15분 기다리세요. 잊었으면 PC에서 `set_passcode.cmd` 실행 |
| "Register this PC's IP in Toss" | 집 인터넷 주소가 바뀜. 새 주소를 토스에 등록 (2.1절 3단계) |
| 휴대폰에서 승인 버튼이 회색 | 휴대폰 전송이 꺼져 있거나(8.4절), 시장가 주문이거나, PIN을 안 넣음 |

## 8b. 클라우드 서버 (항상 켜 두기)

대시보드를 서울의 작은 AWS Lightsail 서버에서 계속 실행할 수 있습니다. 그러면 PC를 꺼도 데이터, 채팅,
활성화한 자동 규칙이 계속 작동합니다. 내 기기만 Tailscale로 접속할 수 있고 인터넷에는 아무것도 열리지 않습니다.
설계와 이유는 [docs/plans/CLOUD_PLAN.md](docs/plans/CLOUD_PLAN.md)(영어)에 있습니다.

**사본 두 개, 역할 두 개:** **서버가 실제로 쓰는 사본**이고, **PC는 작업용 사본**이 됩니다. 수정과 테스트는 PC에서
하고 GitHub에 올린 뒤, 서버는 명령 하나로 업데이트합니다. 서버의 파일을 직접 고치지 마세요.

### 8b.1 AWS (처음 한 번)
1. AWS 계정: 2단계 로그인(MFA)을 켜고 결제 알림을 만듭니다(예: 월 20 USD).
2. **Lightsail → 인스턴스 생성**: 리전 **서울(ap-northeast-2)**, 플랫폼 **Linux/Unix**, 블루프린트
   **OS 전용 → Ubuntu**(가장 최신 LTS), 플랜 **2 GB**. 이름은 예를 들어 `trading-desk`.
3. **네트워킹 → 고정 IP 생성** 후 인스턴스에 연결합니다. IP를 적어 둡니다.
4. 인스턴스 → **스냅샷 → 자동 스냅샷: 켜기**.
5. 방화벽은 지금은 기본값 그대로 둡니다(Tailscale이 될 때까지 SSH가 필요). 8b.3에서 지웁니다.

### 8b.2 Toss (처음 한 번)
Toss Open API 콘솔에 서버의 고정 IP를 등록합니다. 문서에 답이 없는 두 가지도 확인하세요: 집 IP도 같이 등록해 둘 수
있는지, 클라우드 서버에서 실행해도 되는지.

### 8b.3 서버에 Tailscale (처음 한 번)
1. Lightsail → 인스턴스 → **SSH를 사용하여 연결**(브라우저에 터미널이 열림).
2. https://tailscale.com/download/linux 에 나온 명령 한 줄로 Tailscale을 설치하고 `sudo tailscale up --ssh`를
   실행한 뒤 출력된 링크를 엽니다. PC·휴대폰과 **같은 계정**으로 로그인합니다.
3. PC에서 PowerShell을 열고 `ssh ubuntu@trading-desk`(서버의 Tailscale 이름)를 실행합니다. Tailscale이 확인을 위해
   브라우저를 열 수 있습니다. 이제부터는 브라우저 터미널 대신 이것을 씁니다.
4. Lightsail → 인스턴스 → **네트워킹**: 방화벽의 **SSH**, **HTTP** 규칙을 지웁니다. 이제 서버로 들어오는 공개 경로가 없습니다.

### 8b.4 코드 받기 (처음 한 번)
서버 터미널(`ssh ubuntu@trading-desk`)에서 한 줄씩:
```
sudo useradd --create-home --shell /bin/bash trading
sudo -u trading -H ssh-keygen -t ed25519 -N "" -f /home/trading/.ssh/id_ed25519
sudo cat /home/trading/.ssh/id_ed25519.pub
```
출력된 줄(`ssh-ed25519`로 시작, 공개 키라서 복사해도 안전)을 복사합니다. GitHub: 내 저장소 → **Settings → Deploy keys →
Add deploy key**에 붙여 넣고 이름은 `trading-desk server`, **Allow write access는 끈 채로** 둡니다. 그다음:
```
sudo install -d -o trading -g trading /opt/trading-desk
sudo -u trading -H git clone git@github.com:<내-github-이름>/Trading-desk.git /opt/trading-desk
```
처음에 GitHub 지문 질문이 나오면 `yes`라고 답합니다.

### 8b.5 설치하고 시작 (처음 한 번, 약 10분)
```
cd /opt/trading-desk
sudo bash scripts/linux/setup.sh
```
모두 설치한 뒤 아직 빠진 것을 알려 줍니다. 아래 세 가지를 하고 `setup.sh`를 한 번 더 실행합니다:
1. **키:** `sudo -u trading -H nano /opt/trading-desk/.env`로 열어 `env.example`과 같은 줄을 내 값으로 입력합니다
   (가능하면 월 사용 한도를 건 **별도의 Anthropic 키**). Ctrl+O, Enter, Ctrl+X로 저장. 이건 직접 입력하고, 키를 채팅에
   절대 붙여 넣지 마세요.
2. **접속 비밀번호와 PIN:** `sudo -u trading -H bash -c 'cd /opt/trading-desk/backend && .venv/bin/python -m app.set_passcode'`
3. **서버 설정:** `sudo -u trading -H nano /opt/trading-desk/data/config.local.yaml`에:
   ```yaml
   remote:
     allow_remote: true
     allowed_logins: ["you@example.com"]   # 내 Tailscale 로그인
   ```
   이 파일은 git에 없어서 업데이트가 덮어쓰지 않습니다. `config.yaml`의 어떤 항목이든 여기 넣을 수 있습니다.

`setup.sh`가 **"The dashboard is running"**이라고 하면 `sudo tailscale serve --bg 8000`을 실행합니다. 주소
`https://trading-desk.<내-tailnet>.ts.net`이 출력됩니다. PC에서 열고 로그인합니다.

### 8b.6 신뢰하는 기기
서버에서는 모든 기기가 "다른 기기에서 접속"으로 취급되어 주문과 활성화 때 PIN을 묻습니다. PC 브라우저에서
**⚙ 설정 → 신뢰하는 기기**를 열고 이름과 PIN을 한 번 입력하면, 그 브라우저는 집 PC처럼 작동합니다(PIN 없음, 일반 주문
규칙). 휴대폰은 따로 신뢰하지 않는 한 계속 PIN을 묻습니다. 기기는 언제든 거기서 지울 수 있고, `set_passcode`를 다시
실행하면 모두 지워집니다.

### 8b.7 처음에는 DRY RUN
서버는 DRY RUN으로 시작합니다(git의 `config.yaml`). 며칠 돌려 보세요. 실제 주문은 직접 결정할 때만:
`data/config.local.yaml`에 `orders:` / `  dry_run: false`를 넣고 `sudo systemctl restart trading-desk`를 실행합니다.
먼저 설정에서 주문당·하루 한도를 정해 두는 것을 권합니다. 활성화한 규칙은 자는 동안에도 실행됩니다.

### 8b.8 작업용 사본이 된 PC
PC에서 `data/config.local.yaml`을 만들고:
```yaml
deploy:
  role: workshop
```
`start.cmd`를 다시 시작합니다. 보라색 **작업용 사본** 줄이 나오고, DRY RUN이 강제로 켜지며 자동 규칙은 꺼집니다.
**Toss는 키 하나에 로그인 토큰 하나만 허용합니다.** PC와 서버가 같은 키로 동시에 돌면 한쪽이 다른 쪽을 로그아웃시킵니다.
PC에서 실제 Toss 데이터로 테스트하려면 먼저 서버를 멈추고, 끝나면 다시 켜세요(아래 명령).

### 8b.9 자주 쓰는 명령 (`ssh ubuntu@trading-desk` 안에서, `/opt/trading-desk` 기준)
| 할 일 | 명령 |
|---|---|
| GitHub 최신 버전으로 업데이트(먼저 테스트, 실패하면 알아서 되돌림) | `sudo bash scripts/linux/update.sh` |
| 이전의 정상 버전으로 되돌리기 | `sudo bash scripts/linux/update.sh --rollback` |
| 실제 사본 멈춤 / 다시 시작(멈춘 동안 활성화한 규칙은 실행되지 않음) | `sudo bash scripts/linux/pause.sh` · `sudo bash scripts/linux/resume.sh` |
| 실행 중인가? | `systemctl status trading-desk` |
| 실시간 로그(Ctrl+C로 나가기) | `journalctl -u trading-desk -f` |
| 지금 백업(매일 07:00 KST에도 자동, 14일 보관) | `sudo -u trading bash scripts/linux/backup.sh` |
| 백업을 PC로 복사 | 서버에서 `sudo install -m 600 -o ubuntu backups/desk-….tar.gz ~/`, PC에서 `scp ubuntu@trading-desk:desk-….tar.gz .`, 그다음 서버에서 `rm ~/desk-….tar.gz` |
| 백업 복원 | `sudo systemctl stop trading-desk` → `sudo -u trading tar -xzf backups/desk-….tar.gz -C /opt/trading-desk` → `sudo systemctl start trading-desk` |

백업에는 `data/`와 `logs/`만 들어갑니다. `.env`와 `secrets/`는 빠지고, 서버 전체는 Lightsail 스냅샷이 보관합니다.

### 8b.10 안 될 때
| 문제 | 할 일 |
|---|---|
| `setup.sh`가 Python 3.15에서 멈춤 | 나중에 다시 실행하고, 계속 실패하면 마지막 몇 줄을 Claude Code에 알려 주세요 |
| 주소가 안 열림 | `systemctl status trading-desk`가 실행 중? `tailscale serve status`에 8000번 포트? PC의 Tailscale이 켜져 있나? |
| "access from other devices is off" | `data/config.local.yaml`에 `remote: allow_remote: true`가 없음. 고치고 `sudo systemctl restart trading-desk` |
| "this Tailscale account is not allowed" | `allowed_logins`의 로그인이 Tailscale에 표시된 것과 철자가 다름 |
| IP 관련 Toss 오류 | Toss 콘솔에 고정 IP가 등록되지 않음(8b.2) |
| 한쪽 사본에 Toss "토큰 교체" | PC와 서버가 같은 키를 동시에 씀(8b.8) |
| 시장 정보 칸·옵션 패널 오류 | Yahoo가 클라우드 서버를 막을 수 있음(알려진 문제, 지금은 감수) |
| `update.sh`가 서버에서 파일이 바뀌었다고 함 | 누군가 서버에서 git 파일을 고침. 고치지 말고 서버 설정은 `data/config.local.yaml`에 넣으세요 |

## 9. 확인 목록

### 1단계 확인 목록

1. ☐ `scripts\start.cmd`를 실행하고 http://127.0.0.1:8000 을 열고 로그인했을 때, 노란 띠에 Toss 관련 문제가 없다.
2. ☐ 차트에 **SOXS** **5분봉**이 나오고:
   - ☐ EMA 9/20/60 라인(하늘색, 주황, 보라)
   - ☐ VWAP(흰색 점선)
   - ☐ 피보나치 레벨("Fib 0.618" 등이 붙은 올리브색 점선)
   - ☐ 주황색 **Avg** 라인(`positions.json`에 매수 기록이 하나 이상 있어야 함)
3. ☐ 시장 정보 띠가 갱신된다: SOXS / SOXX 아래 "N초 전 업데이트"가 몇 초 이내, USD/KRW는 약 1분 이내.
4. ☐ SOXX → 1분봉 → 일봉으로 바꿀 때마다 차트가 바뀐다.
5. ☐ 계획을 추가하면(예: 매수, `3.95`, USD) 초록 라인이 생기고 `positions.json`에 들어간다. 다시 삭제한다.
6. ☐ 브라우저 창을 좁히면(또는 F12 → 휴대폰 크기 선택) 아래쪽에 탭이 나타난다.

### 2단계 확인 목록
1. ☐ `scripts\check_models.cmd`가 "All model IDs found"를 표시한다.
2. ☐ **"SOXS 5분봉 지지선은 어디야?"**라고 물으면 답에 레벨 id가 붙고, 그려 달라고 하면 차트에 하늘색 AI 라인이 나타난다.
3. ☐ **AI 라인** 표시 선택이 AI 라인만 숨기고 보인다.
4. ☐ **시나리오**를 물으면 손익비와 비용 차감 후 움직임이 있는 표가 나온다.
5. ☐ **일반 → 심층 → 최심층**으로 바꿔 가며 짧게 물으면 비용 줄에 Sonnet, Opus, Fable 순서로 표시된다.
6. ☐ 답변마다 비용이 나오고, 헤더에 오늘과 이번 달 사용액이, 손익 패널에 AI 크레딧이 나온다.

### 3단계 확인 목록
1. ☐ **호가창**에 SOXS의 매도/매수 호가, 스프레드, 세션이 나오고, 장중에는 **실시간**으로 표시되며 체결 목록이 움직인다. 맨 위에 나오는 Toss 호가 단수를 확인한다.
2. ☐ 차트 종목을 바꾸면 호가창도 따라 바뀐다.
3. ☐ `FINNHUB_API_KEY`를 넣으면 몇 분 안에 **뉴스** 패널이 채워지고, 항목마다 중요도·영향·이유가 붙는다(중요도 높음은 빨강).
4. ☐ 채팅에 **"NVDA 중요한 뉴스 있어?"**라고 물으면 피드의 제목, 링크, 날짜, 중요도로 답한다.
5. ☐ 랜선을 뽑거나 와이파이를 1분 끄면 호가창에 "연결 끊김, 재시도…"가 나오고, 나머지는 계속 작동하며, 다시 연결되면 스스로 **실시간**으로 돌아온다.

### 4단계 확인 목록 (DRY RUN)
1. ☐ 주문 탭에 파란 **DRY RUN** 줄, 내 계좌(가려진 번호), 주문가능금액, 보유 종목, 미체결 주문이 토스 앱과 같게 보입니다.
2. ☐ SOXS 1주를 현재가보다 조금 낮게 **매수** 초안을 만듭니다: 요약 문장과 남은 시간이 나옵니다. 10% 떨어진 가격으로 해 보면 범위를 벗어났다고 나옵니다.
3. ☐ **검토 후 승인**: 결과가 *모의(DRY RUN)*로 나옵니다. **모의 주문** 목록과 차트의 DRY RUN 점선에 나타납니다. 토스 앱에는 아무것도 없습니다.
4. ☐ 그 모의 주문에서 **가격 정정** 후 승인: 이전 것은 *REPLACED*, 새 것은 *OPEN*. 그다음 **취소** 후 승인: *CANCELED*.
5. ☐ **예약 매도**와 **OCO**를 만들어 봅니다: 만료일이 필요하고, 감시가 순서가 반대인 OCO는 거절됩니다.
6. ☐ 채팅에 시나리오 두 개를 요청하고 카드의 **진입가 매수**를 누릅니다: 주문서가 채워지고, 수량을 넣어 초안을 만들고 승인합니다.
7. ☐ 채팅에 *"SOXS 1주 4.25 지정가 당일 매수"*(현재가 근처 가격)를 입력: 주문 탭에 초안이 생깁니다. *"SOXS 4.25에 매수"*를 입력: AI가 대신 수량과 유효기간을 물어봅니다.
8. ☐ `logs\trades.jsonl`을 메모장으로 엽니다: 전송마다 `request`와 `result` 줄이 있고 `"dry_run":true`, 키는 없습니다.
9. ☐ 손익(보유 종목)이 토스 앱과 맞고, 차트에 과거 체결의 B/S 표시가 있고, 매매일지는 이 프로그램으로 한 거래가 아직 없다고 나옵니다.

### 5단계 확인 목록
1. ☐ `set_passcode.cmd` 완료. http://127.0.0.1:8000 에서 암호를 묻고, 틀리면 남은 횟수가 나옵니다.
2. ☐ `tailscale serve --bg 8000`이 `https://….ts.net` 주소를 보여 줬고, `tailscale serve status`에도 보입니다.
3. ☐ 휴대폰에서 Tailscale을 켜고(집 와이파이 말고 모바일 데이터로) 주소를 열면 로그인이 나오고, 로그인하면 차트, 손익, 채팅, 호가, 뉴스가 보입니다.
4. ☐ 휴대폰에서 Tailscale을 끄면 주소가 더 이상 열리지 않습니다.
5. ☐ 휴대폰에서 초안을 만들고 검토 후 승인을 누르면, 휴대폰 전송이 꺼져 있다고 나옵니다.
6. ☐ 휴대폰 홈 화면에 앱이 있고 전체 화면으로 열립니다.

### 6단계 확인 목록
1. ☐ 리서치 → 랭킹: 오늘 미국 거래량 랭킹이 나오고, 섹터를 열면 종목이 나옵니다. 종목 3개를 ★로 폴더에 넣고 고정하면, 재시작 후 차트 빠른 버튼과 시장 정보 띠에 나옵니다.
2. ☐ 기업 화면 위 검색창에서 NVDA: 개요 타일, 5년 재무제표, 최근 4분기 EPS 서프라이즈, 의견 분포, (비공식) 목표가 범위. SOXS는 ETF 카드, TSM은 TWD 재무제표와 배수 계산 거부 사유가 나옵니다.
3. ☐ NVDA 리서치 채팅에서 **밸류에이션**: 판단 3개짜리 카드가 나오고, 카드의 모든 숫자가 기업 화면에도 있습니다.
4. ☐ **투자 논리 저장**에서 "과거 중앙 P/E 기준 가격"을 체크한 채 저장: 투자 논리 카드가 나오고, 데스크의 내 정보 위에 카드가, 차트에 보라색 점선이 나옵니다. **투자 논리 라인** 토글로 숨길 수 있습니다.
5. ☐ 리서치 채팅에 "저장하지 마": 저장되지 않습니다. 새 카드 뒤 "저장해줘": 저장되고 "요청에 따라 AI가 저장"으로 표시됩니다.
6. ☐ 데스크에서 SOXX로 바꿨다가 NVDA로 돌아오면 종목마다 자기 채팅이 나옵니다.

## 10. 문제가 생겼을 때

| 화면 표시 | 할 일 |
|---|---|
| "백엔드에 연결할 수 없습니다" | `scripts\start.cmd`가 실행 중이 아니거나 멈췄습니다. 다시 실행하고 그 창의 오류를 읽어 보세요 |
| ".env에 설정되지 않음: TOSS_CLIENT_ID, …" | `.env`를 채우고(2.4절) 다시 실행하세요 |
| "Toss WTS(설정 > Open API)에 이 PC의 IP를 등록하세요" | 2.1절 3단계를 하고 1분쯤 기다리세요 |
| "다른 곳에서 토큰이 교체됨" | 다른 창에서 대시보드가 실행 중입니다. 그 창을 닫고 **Toss 다시 시도**를 누르세요 |
| 시장 정보 칸에 **갱신 멈춤** | 그 데이터 출처가 갱신을 멈췄습니다. yfinance는 비공식이라 가끔 실패하며, 간격을 늘려 가며 자동으로 다시 시도합니다 |
| "10Y ^TNX"에 **단위?** | ^TNX와 FRED 값이 1포인트 넘게 다릅니다(출처의 단위 문제). FRED 일별 값을 믿으세요 |
| 손익에 `positions.json` 오류 | 표시된 줄과 칸의 JSON을 고치세요 |
| 채팅에 "키 없음" | `.env`에 `ANTHROPIC_API_KEY`를 넣고(2.3절) 다시 실행하세요 |
| 채팅에 "요청 한도 초과 또는 크레딧 부족" | Anthropic Console의 Billing을 확인하세요 |
| 채팅에 "model not found" | `scripts\check_models.cmd`를 실행하고 `config.yaml`의 모델 ID를 고치세요 |
| "예산 한도 도달" | 다음 날이나 다음 달(KST)까지 기다리거나, `config.yaml`의 `budget:`을 올리세요 |
| 호가창이 계속 "연결 끊김" | 노란 띠의 Toss 문제(IP, 토큰)를 확인하세요. 그동안 2초마다 조회로 계속 작동합니다 |
| 호가가 1–2단만 나옴 | 미국 주식은 Toss가 그만큼만 줍니다(일부 미국 거래소 기준, 전체 시장 호가 아님) |
| 뉴스에 "요청 한도 초과" | Finnhub 무료 한도에 걸렸습니다. 다음 회차(5분마다)에 다시 시도합니다. `news.related` 종목을 줄이면 도움이 됩니다 |

| 주문 탭: "주문가능금액을 아직 불러오지 못했습니다" 또는 계좌 없음 | 10초 기다리고 노란 줄에서 토스 문제를 확인. 계좌가 여러 개면 `config.yaml`의 `orders.account_seq` 설정 |
| 전송 결과가 `unknown` | 다시 시도하기 전에 미체결 주문(주문 탭 / 토스 앱) 확인 (7.7절) |

**폴더** (프로젝트 폴더 기준):

| 폴더 / 파일 | 내용 |
|---|---|
| `backend/` | Python 서버(`app/`)와 테스트(`tests/`) |

| `logs/` | 주문 기록, AI 사용량, 채팅·뉴스 데이터베이스(git에 안 들어감) |
